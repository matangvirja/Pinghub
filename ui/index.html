Load Lab in-app

Runs virtual users against the real gateway. Every user has its own rate-limit bucket. At the end you get a PASS / FAIL robustness verdict.

requests / sec queue depth idle
What does PASS mean?0 server errors, every accepted message delivered or permanently failed, and the queue fully drains.
Why are there 429s?The token-bucket limiter rejected excess requests. That is protection working, not a failure.
What if WARN / FAIL?The queue did not drain or the gateway returned 5xx. Add workers or reduce the arrival rate.
